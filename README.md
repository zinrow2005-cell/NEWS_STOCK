# 安心股票簿｜GitHub Pages 直接上傳版

這個資料夾中的檔案已經建置完成，不需要安裝 Node.js，也不需要執行任何指令。

## 上傳方式

1. 解壓縮 ZIP。
2. 進入解壓縮後的資料夾，選取裡面的全部檔案與資料夾。
3. 上傳到 GitHub repository 的最外層，確認 `index.html` 位於最外層，不能再多包一層資料夾。
4. 到 repository 的 **Settings → Pages**。
5. 在 **Build and deployment** 選擇 **Deploy from a branch**。
6. Branch 選擇 `main`，資料夾選擇 `/(root)`，按 **Save**。
7. 等候 GitHub Pages 完成發布，再開啟 GitHub 提供的網址。

## 正確的最外層結構

```text
index.html
404.html
assets/
manifest.webmanifest
service-worker.js
offline.html
icon-192.png
icon-512.png
stock-directory.json
```

只要 GitHub 最外層可以直接看到 `index.html`，GitHub Pages 網址打開後就會直接進入「安心股票簿」，不會再顯示 README 說明頁。

## v3.2.0 新聞追蹤清單＋已讀／待追蹤

新聞情報中心新增 **「我的追蹤」** 分頁。使用者可以從每日市場情報、新聞列表或全台股事件雷達，把重要事件標記為追蹤，並自行切換已讀／未讀狀態。

追蹤不是單純收藏連結。每個追蹤主題會保存股票代號、原始事件、事件類型與主題關鍵詞；之後 GitHub Actions 更新 `stock-news.json` 後，只要有同公司且主題／事件類型相近的新新聞，就會自動集中到同一追蹤串並以未讀顯示。追蹤起點在加入時會自動標記為已讀。

追蹤頁可：

- 查看追蹤主題與未讀後續數量
- 搜尋公司／事件主題／關鍵詞
- 只看有未讀更新的追蹤串
- 將整個追蹤串標記為全部已讀
- 取消追蹤
- 回到原始新聞或直接進入個股情報研究

追蹤資料與已讀狀態使用瀏覽器 `localStorage` 保存，不需要 Firebase 或額外資料庫。這也代表不同瀏覽器／手機／iPad 之間目前不會自動同步追蹤狀態。

## v4.3 備份版本歷史與差異比較

v4.3 在 v4.2 的備份還原中心加入 A/B 版本比較。比較本身是唯讀操作，不會修改目前資料。

可比較來源：
- 目前本機研究資料
- 最近 6 個本機還原點
- 外部 JSON 備份 A
- 外部 JSON 備份 B

差異會整理為：
- 新增追蹤事件
- 刪除追蹤事件
- 修改追蹤事件
- 已讀筆數變化

- 待辦新增、刪除、完成狀態變化
- 研究假設、待驗證條件、關鍵證據、筆記、驗證結果、結案摘要的前後差異
- 研究回顧、判斷偏差、可複用教訓與回顧摘要的前後差異

建議使用方式：把較舊版本放在 A、較新版本放在 B，再按「比較兩個版本」。先確認差異後，再決定是否需要執行還原。

## v4.4 同步衝突逐項合併

v4.4 延續 v4.3 的 A/B 差異比較，加入「逐項合併」工作流。比較完成後，使用者可以針對每一個衝突分別決定採用版本 A 或版本 B，而不是只能整份覆蓋。

支援逐項選擇：
- 只存在 A 或只存在 B 的追蹤事件：保留、加入或刪除
- 研究狀態與結案狀態
- 研究假設、待驗證條件、關鍵證據、研究筆記
- 驗證結果與結案摘要
- 研究回顧、判斷偏差、可複用教訓與回顧摘要
- 待辦新增／刪除／內容與完成狀態
- 已讀紀錄與刪除墓碑可整體選 A 或 B

每個修改過的研究都有「全部 A／全部 B」快捷鍵，也可繼續逐欄位調整。選擇完成後必須先按「產生合併預覽」；預覽只計算合併後資料，不會修改目前研究資料。預覽可下載為獨立 JSON，或在再次確認後套用到目前本機資料。正式套用前會自動建立「套用合併前」還原點。

建議流程：先用 v4.3 的 A/B 比較確認差異 → 在 v4.4 逐項選擇 → 產生合併預覽 → 必要時先下載合併 JSON → 最後才套用。


## v4.5.0 三方同步合併

本版將跨裝置同步升級為三方合併：系統會保存「上一次成功同步後的共同基準 Base」，之後同步時比較 Base、本機 A、雲端 B。

- 只有 A 修改：自動採 A。
- 只有 B 修改：自動採 B。
- A、B 修改成相同內容：自動合併。
- A、B 同時修改同一欄位且結果不同：列為真正衝突，智慧同步暫停。
- 「一邊刪除、一邊修改」會列為真正衝突。
- 同一刪除紀錄只有時間戳不同不會誤報衝突。
- 三方衝突頁會顯示 Base / A / B 三欄內容，可逐項選擇 A 或 B。
- 套用三方合併前會自動建立還原點；也可先下載三方合併 JSON。
- 衝突解決完成後會回寫 Google Sheet，並把結果更新為新的共同 Base。

第一次使用 v4.5 時，如果尚無共同 Base，完成一次成功的「上傳本機」或「智慧三方同步」後就會建立。之後多裝置各自修改時，系統才有能力精準判斷哪些是單邊變更、哪些是真正衝突。

## v4.7 裝置命名與完整修改稽核

在「我的追蹤 → 跨裝置同步」可設定此裝置名稱，例如「家裡電腦」「iPad Air 5」「手機」。之後研究狀態、研究假設、驗證條件、關鍵證據、研究筆記、驗證結果、結案摘要、研究回顧，以及手動待辦新增／完成狀態的修改，都會記錄時間、裝置、修改前與修改後內容。

每個追蹤事件的「研究修改時間線」會優先顯示完整修改紀錄。為避免同步資料無限成長，全域稽核紀錄最多保存最近 500 筆。舊版資料沒有歷史 audit 時仍會顯示原本的「最後修改來源」。
